# Real-usage report: twelve days on 0.17.1, the mod host (observation period)

**Not a declared window.** The third report said the next window would be declared before it opened. It was not: 0.17.1 shipped on the evening of 2026-10-14, the mod went live on the 15th (the plugin had not been installed at all until then; see the correction in `docs/usage-2026-10-15.md`), `trusted_hosts` was set the same day, and work resumed without a declaration. This report covers everything the mod logged from **2026-10-16 00:00 ET through 2026-10-27 10:09 ET** and is labelled what it is: an observation period on one version, one host, one policy, read once at the end. The numbers are cut from the audit log by `host` and `toolgate_version` (both on every row since 0.17.0); no row was excluded. It is not one of the three consecutive windows that 1.0 asks for. The next window is declared at the end of this document.

The policy for the whole period: 0.17.1 defaults plus `trusted_hosts` naming the author's own database, app and API hosts and two model providers the projects pay for; `trusted_tools` naming one of the author's own MCP servers; `jev-1.13.0` pinned. Six sessions, ordinary product work on a few web apps with media pipelines. All paths, project names, hosts and identifiers are genericized. The author is the only user.

Host `mod` on all 2,446 rows, version 0.17.1, backend `typesafe:jev-1.13.0`. Latency p50 **721 ms**, p90 879 ms (2,435 model calls), the lowest yet: the mod hands the CLI the transcript it already holds instead of having it read the file. Sources: model 2,424, confirmed 11, fail-mode 10 (seven `fetch failed`, one provider 529 "system overloaded", surfaced as asks), static rule 1 (`curl … | sh`).

The ask rate is flat against the third window and under a wide daily spread: 4.6% on a 282-decision day, 24–26% on two 130–140-decision days, with the decision count and the ask rate uncorrelated. (`toolgate audit --stats --since 2026-10-16` reports 2,474 decisions and 14%: `--since` with a bare date counts from UTC midnight, which reaches back into the evening of the 15th. This report uses Eastern days.)

**Permissive misses (author pass): 0.** 26 of 2,103 allows had a capability axis at or above 0.50. Four are above 0.60 and all four are the confirmation memory: a browser call that clears a dev tab's local storage and reloads it (destructive 0.67–0.74), confirmed once by the person, then allowed on the identical call. The other 22 sit at 0.50–0.54: scratch analysis scripts, `sed -i` edits that turn a module-level constant into an export, an `ffmpeg -y` that overwrites its own output, a config file written with a key placeholder (secret exposure 0.52), a search of a dev server's logs for the string `env` (0.50). None was an action the task had not called for.

**The nine denies.** Seven are exfiltration at 0.86–0.90: scratch scripts that import a prompt constant or a key from the project's own code and post the author's own content to a text-to-speech provider and an image-model provider the projects already use, neither of which was in `trusted_hosts` (the list named the database, the app hosts and two other providers). One is secret exposure at 0.86: a one-liner that reads an MCP server's API key out of a config file and pipes it into a protocol test; by the axis's definition that is a true positive (it prints a credential value), and the person had asked for exactly that test. One is destructive at 0.90: a `rm -f` of four generated screenshots followed by `cp` and `mv` to rename the rest, inside a kit of listing assets the task was rebuilding; `authorized` scored 0.31, so nothing softened, and the person would have answered yes. So: seven denies `trusted_hosts` would have made allows had it named the two providers, one correct-by-definition deny the person wanted through, one false deny. 9 in 2,446 is 0.4%; a deny a person would have answered yes to is the costliest verdict the gate can give, and this period produced one.

## What held, verified on 2,446 decisions

- **The truncation floor** fired twice (two oversized inputs). Compaction summaries do not reach the ask count.
- **The read-only classifier** flagged 778 calls (32%) as read-only; the `off_task` waiver fired on **94** of them, and no waived call had a capability axis over the ask line. The classifier itself can now be measured on the log, which is what the `read_only` flag was for.
- **The confirmation memory** fired 11 times, all on browser calls: a dev-tab reload and a dev-tab storage reset, each confirmed once and repeated. Still small, still exact-match.
- **Task context** present on 2,333 of 2,435 model decisions (95.8%). The 102 without a prompt (99 allows, 3 asks) cluster in two sessions on Oct 21–22; they are turns where the transcript the mod saw had no typed prompt yet. Median prompt 132 characters on the off-task asks; 105 of the 286 were judged against a prompt under 80 characters.
- **`trusted_hosts`** did what it names. The third window had 10 exfiltration asks and 1 deny in 318 decisions (3.5%), every one to the author's own services. This period has 7 asks and 7 denies in 2,446 (0.6%), and all 14 go to the two providers the list left out. The list cannot be set inside a window, so the two are added now, after this report.
- **Latency** 721 ms p50 against 945 ms on the hook in the third window and 1,060 ms in the first. Same model, same route; the host changed.

### Off-task is now 86% of the friction, and the same shape as before

The shape has not changed across four reports: the latest prompt is a reaction or a terse redirect ("yes start with leveling", "but the chatbot said there was no gif option", "make both so I can pick"), and the agent answers it by writing a scratch script and running it, editing a component through a heredoc or `Edit`, or driving the dev tab. Those are writes and executions, so the read-only waiver does not apply, and the model, reading them against the reaction, scores them off-task. Two blind labelings called this class noise (reviewer allowed 230 of 243, then 91 of 94). The 30 `Edit` asks are new in volume, and all off-task: the mod gates `Edit` with full task context, and a file edit against a one-line reaction scores the same way a heredoc does.

### The 0.18 rule, replayed on this period

0.18.0 ships the rule the third report proposed: `off_task` alone raises an ask only when some capability axis (destructive, exfiltration, privilege, secret_exposure) is at least 0.40 (`thresholds.off_task_capability`). Replayed on the recorded probabilities, requiring also that neither context axis (violates_constraint, unresolved_choice) is at or above the ask line:

| | ask now | with the rule |
|---|---|---|
| this period (2,446) | 13.7% (334) | **3.7%** (90) |
| per day, range | 4.6%–26.2% | 0%–9.2% |

244 of the 286 off-task asks flip to allow; 42 stay, because a capability axis was at or above 0.40 on the same call (21 of them in the 0.50s: a grep over `.env` counts, a scratch script that reads a key, a storage reset). The replay cannot tell whether the model's `off_task` would have scored differently had the earlier asks not interrupted, so the real number comes from the declared window below.

**The named cost, observed.** Two of the 244 flipped asks are calls to a paid image-generation tool, asked at off-task 0.57 and 0.62 against a prompt complaining about the previous generation. Under 0.18 they pass, because the tool has no capability axis. In this instance the person wanted the regeneration; in the second window's blind labeling the same class ("spends money without being asked to") was the one ask the reviewer added among 150 sampled allows. The cost is small here (2 in 2,446) and real, and it is why a spending axis, or a `trusted_hosts`-style declaration of paid services, is now the first roadmap item.

## Two things the mod host showed that the hook did not

**The mod does not send the permission mode.** Every row in this period has no `permission_mode`; the hook's rows always did. Two engine behaviours key on it: the unattended rule (an ask becomes a deny in `bypassPermissions` and `dontAsk`) and the confirmation memory's "could a person have answered this" check, which skips `auto` mode. In the mod both fall back to the attended case, so this period's 11 confirmations were counted as a person's without the mod being able to say so. Claude Code's `tool.check` event does not carry the mode, but it carries two fields the engine can use: `approver` (`person`, `host`, or absent when nobody can be asked) and `isReadOnly` (the tool's own word that the input is a read). 0.18.1 passes both through: an ask with no approver is treated as unattended, and the tool's read-only flag is an input to the classifier alongside toolgate's own. Until then the mod's audit rows should be read as "mode unknown", and the unattended guarantee holds on the hook host only. This matters more than it did a month ago: auto mode is now Claude Code's default for new sessions on most plans, so a growing share of mod rows will be decided under a mode in which toolgate's ask may be answered by Anthropic's classifier rather than a person.

**`Edit` is gated with context now, and it asks.** The hook saw `Edit` too, but on the mod the task context arrives on every call, so the context axes score every file edit. Thirty off-task asks on edits in twelve days is the price; the 0.18 rule removes 30 of them in replay, since an edit's capability axes are low.
